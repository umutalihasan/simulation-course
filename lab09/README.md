## Теоретическая основа

В модели `M/M/1`:

- входящий поток клиентов является простейшим пуассоновским потоком с интенсивностью `λ`;
- интервалы между поступлениями имеют экспоненциальное распределение;
- время обслуживания имеет экспоненциальное распределение с параметром `μ`;
- обслуживающий прибор один;
- дисциплина очереди - `FIFO`.

Интервалы моделируются через равномерную случайную величину `U`:

```text
τa = -ln(U) / λ
τs = -ln(U) / μ
```

Коэффициент загрузки системы:

```text
ρ = λ / μ
```

Стационарный режим существует при условии:

```text
ρ < 1
```

Для устойчивой системы `M/M/1` теоретическое распределение числа клиентов в системе:

```text
P{N = n} = (1 - ρ)ρ^n, n = 0, 1, 2, ...
```

Основные теоретические показатели:

```text
L  = ρ / (1 - ρ)
Lq = ρ² / (1 - ρ)
W  = 1 / (μ - λ)
Wq = ρ / (μ - λ)
```

где:

- `L` - среднее число клиентов в системе;
- `Lq` - среднее число клиентов в очереди;
- `W` - среднее время пребывания клиента в системе;
- `Wq` - среднее время ожидания в очереди.

Для времени ожидания в очереди:

```text
P{Wq = 0} = 1 - ρ
P{Wq > t} = ρ · exp(-(μ - λ)t)
```

## Дискретно-событийный алгоритм

В модели используются два типа событий:

1. поступление клиента;
2. окончание обслуживания.

Состояние системы описывается переменными:

- текущее модельное время `t`;
- момент следующего поступления `ta`;
- момент следующего окончания обслуживания `td`;
- состояние оператора: свободен или занят;
- очередь клиентов;
- накопленное время пребывания системы в состояниях `N = 0, 1, 2, ...`;
- массив времен ожидания клиентов в очереди.

Алгоритм:

1. Установить `t = 0`, очередь пустая, оператор свободен.
2. Сгенерировать момент первого поступления клиента.
3. Выбрать ближайшее событие: `min(ta, td)`.
4. До перехода к событию добавить длительность интервала к текущему числу клиентов в системе.
5. Если произошло поступление:
   - если оператор свободен, клиент сразу начинает обслуживание;
   - иначе клиент добавляется в очередь;
   - генерируется следующее поступление.
6. Если произошло окончание обслуживания:
   - если очередь пустая, оператор освобождается;
   - иначе первый клиент из очереди начинает обслуживание;
   - генерируется следующее окончание обслуживания.
7. Повторять до конца интервала моделирования.

Начальный участок моделирования используется как прогрев и не входит в статистику.

## Что делает приложение

Приложение `lab9/index.html` позволяет:

- задавать `λ`, `μ`, время наблюдения `T`, прогрев и seed;
- проверять условие устойчивости `λ < μ`;
- моделировать СМО `M/M/1` методом ближайшего события;
- выводить накопительный журнал текущих состояний системы через каждые 100 единиц модельного времени;
- строить частотный полигон числа клиентов в системе;
- строить гистограмму времени ожидания в очереди;
- сравнивать эмпирические и теоретические вероятности;
- вычислять загрузку, `L`, `Lq`, `Wq`, вероятность немедленного обслуживания и вероятность долгого ожидания;
- экспортировать результаты в `.csv`.

## Вывод

При `λ < μ` система `M/M/1` выходит на стационарный режим. Чем ближе `ρ` к единице, тем сильнее растут среднее число клиентов в системе, средняя длина очереди и время ожидания. При увеличении времени наблюдения эмпирический частотный полигон числа клиентов в системе приближается к распределению:

```text
P{N = n} = (1 - ρ)ρ^n
```

а эмпирическая гистограмма времени ожидания становится ближе к теоретическому распределению `Wq`.
